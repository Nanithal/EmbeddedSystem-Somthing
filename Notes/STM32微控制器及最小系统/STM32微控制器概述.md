## 一、STM32 是什么

**STM32** 是意法半导体（STMicroelectronics，简称 ST）基于 **ARM Cortex-M 内核** 的 32 位微控制器产品家族，2007 年推出，如今是**全球使用最广泛的 32 位 MCU 系列**。

一句话概括：

> STM32 = ARM Cortex-M 内核 + ST 自研外设 + 完整固件库与工具链 + 庞大的中文社区

### 为什么这么流行

| 原因 | 说明 |
| --- | --- |
| 生态好 | 资料、例程、教程、开源项目数量碾压其他 MCU |
| 系列全 | 从 8 毛钱的 F0 到 480 MHz 的 H7，覆盖几乎所有需求 |
| 引脚兼容 | 同系列不同型号常可 Pin-to-Pin 替换，方便降本与升级 |
| 工具免费 | STM32CubeMX + CubeIDE + HAL 库全部免费 |
| 供货稳 | 经历缺货潮后 ST 大幅扩产，且有大量国产兼容替代 |
| 开发快 | CubeMX 图形化配置直接生成工程，几分钟点亮外设 |

### 基本特征

- 内核：ARM Cortex-M0/M0+/M3/M4/M7/M33（部分 MPU 用 Cortex-A7/A9）
- 位宽：32 位
- 电压：主流 1.8~3.6 V（部分 1.71~3.6 V），I/O 多为 5 V 容忍
- 封装：TSSOP20 / QFN / LQFP32/48/64/100/144/176 / BGA
- 温度：工业级 −40~85 ℃（部分 −40~125 ℃）
- 编程：SWD/JTAG 调试 + 串口/USB/CAN Bootloader 下载

## 二、命名规则解读

以 **STM32 F 103 C 8 T 6** 为例：

```
 STM32  F     103    C     8     T      6
  │     │      │     │     │     │      │
  │     │      │     │     │     │      └─ 温度范围
  │     │      │     │     │     └──────── 封装类型
  │     │      │     │     └────────────── Flash 容量
  │     │      │     └──────────────────── 引脚数
  │     │      └────────────────────────── 子系列
  │     └───────────────────────────────── 产品系列（F/L/H/G/W/U）

```

### 各字段含义

| 字段 | 取值 | 含义 |
| --- | --- | --- |
| **系列字母** | F | Foundation，主流通用型 |
| | L | Low power，超低功耗 |
| | H | High performance，高性能 |
| | G | General（新一代主流，替代 F1） |
| | W | Wireless，内置无线（BLE/LoRa） |
| | U | Ultra-low-power（新一代低功耗） |
| | MP | Microprocessor，应用处理器（Cortex-A） |
| **子系列数字** | 0 / 1 / 2 / 3 / 4 / 7 | 内核与定位（见下表） |
| **引脚数** | T=36, C=48, R=64, V=100, Z=144, I=176, B=208… | 封装引脚数量 |
| **Flash 容量** | 4=16K, 6=32K, 8=64K, B=128K, C=256K, D=384K, E=512K, F=768K, G=1M, I=2M | 片内 Flash |
| **封装** | T=LQFP, U=QFN, H=BGA, Y=WLCSP, P=TSSOP… | 物理封装 |
| **温度范围** | 6 = −40~85 ℃（工业级）<br>7 = −40~105 ℃<br>3 = −40~125 ℃ | 工作温度 |

### 应用处理器系列（MPU）

| 系列 | 内核 | 主频 | 特点 |
| --- | --- | --- | --- |
| **STM32MP1** | Cortex-A7 双核 + M4 | 650~800 MHz | 跑 Linux + 实时核协同 |

### 选型对照速记

```
只要便宜、简单控制       → C0 / F0 / G0
要经典主流、资料最多     → F1（入门）/ G0 / G4（新设计）
要低功耗、电池供电       → L0 / L4 / U5
要浮点算法、电机控制     → F3 / F4 / G4
要高性能、复杂算法       → F7 / H7
要内置蓝牙或 LoRa        → W 系列
要跑 Linux + 实时        → MP1 / MP2
```

## 五、时钟系统（重点）

STM32 的所有外设都依赖时钟，**时钟树是必须掌握的第一张图**。

### 时钟源

| 时钟源 | 名称 | 频率 | 精度 | 用途 |
| --- | --- | --- | --- | --- |
| HSI | 内部高速 RC | 8 MHz（F1）/ 16 MHz（F4） | ±1~3% | 上电默认、快速启动、HSE 故障备用 |
| HSE | 外部高速晶振 | 4~26 MHz（常见 8 MHz） | 很高 | 主时钟源，经 PLL 倍频 |
| LSI | 内部低速 RC | ~40 kHz | 低 | 独立看门狗、RTC 备份 |
| LSE | 外部低速晶振 | 32.768 kHz | 高 | RTC 精确走时 |
| PLL | 锁相环 | 倍频（F1 最高 ×16） | — | 产生 SYSCLK |

### F1 时钟树实例（8 MHz 晶振 → 72 MHz）

```
HSE 8 MHz ──→ PLL（×9）──→ 72 MHz = SYSCLK
                                 │
                    ┌────────────┴────────────┐
                 AHB 不分频                 (HCLK = 72 MHz)
                    │
        ┌───────────┴────────────┐
     APB2 不分频               APB1 2 分频
     (PCLK2 = 72 MHz)         (PCLK1 = 36 MHz)
     GPIO/USART1/SPI1/ADC     TIM2~7/USART2/I2C/CAN
```

### 关键规则

- **外设使用前必须使能其时钟**（`RCC->APB2ENR` 等寄存器，或 `__HAL_RCC_GPIOA_CLK_ENABLE()`）。
- **APB 预分频 ≠ 1 时，定时器时钟自动 ×2**（常见坑：算波特率/定时周期时忘了）。
- 系统时钟切换失败会导致 HSE 失效，应配置 **CSS（时钟安全系统）** 自动切回 HSI。
- **低功耗模式**：Sleep（内核停）、Stop（时钟停，SRAM 保持）、Standby（几乎全断电，仅备份域）。

## 六、常见外设资源

| 外设 | F1 典型数量 | 说明 |
| --- | --- | --- |
| GPIO | 37~112 个 | 分 A~E 端口，每个 16 位，可复用 |
| USART/UART | 3~5 个 | 异步串口，部分支持同步/智能卡/IrDA |

## 七、开发工具链

| 环节 | 工具 | 说明 |
| --- | --- | --- |
| **图形化配置** | **STM32CubeMX / CubeIDE** | 选型、配引脚、配时钟树、生成工程（最重要） |
| 官方 IDE | STM32CubeIDE（基于 Eclipse） | 免费，集成编译+调试 |
| 第三方 IDE | Keil MDK-ARM、IAR EWARM | 商业，调试体验好，国内常用 |
| 现代组合 | VS Code + CMake + arm-none-eabi-gcc + OpenOCD | 轻量、可 CI，越来越流行 |
| 编译器 | arm-none-eabi-gcc、ARMCC、IAR | GCC 免费且主流 |
| 固件库 | **HAL**（推荐）、LL（轻量）、Standard Peripheral（旧） | HAL 跨系列可移植，LL 效率高 |
| 调试器 | ST-Link V2/V3、J-Link、DAPLink | ST-Link 最便宜常用 |
| 下载方式 | SWD、串口 ISP（BOOT0=1）、USB DFU、CAN/I²C Bootloader | 量产常用 SWD 或 ISP |
| 操作系统 | FreeRTOS（CubeMX 可直接生成）、RT-Thread、ThreadX | 多任务需求时使用 |

### HAL / LL / 标准库对比

| 库 | 特点 | 建议 |
| --- | --- | --- |
| **HAL** | 抽象度高、跨系列、配合 CubeMX，代码量大、效率略低 | 新项目首选，开发快 |
| **LL** | 直接操作寄存器、效率高、代码小 | 追求性能/体积，可与 HAL 混用 |
| **Standard Peripheral** | F1 时代的老库，已停止更新 | 仅维护老项目 |
| **寄存器直编** | 最直观理解硬件，但可移植性差 | 学习阶段建议看，产品少用 |

### 典型开发流程

```
① CubeMX 选型号 → ② 配时钟树与引脚 → ③ 使能外设与中断
→ ④ 生成工程（HAL + CubeIDE/Makefile）→ ⑤ 写应用代码
→ ⑥ 编译下载（SWD）→ ⑦ 在线调试 / 串口打印 → ⑧ 优化与量产
```

## 八、启动过程与存储布局

```
上电/复位
   ↓
① 从 0x0000_0000 取初始 MSP（栈顶地址）      ← 向量表第 0 项
② 从 0x0000_0004 取 Reset_Handler 地址       ← 向量表第 1 项
③ Reset_Handler：配置时钟、使能 FPU（F4）
④ 拷贝 .data 段（Flash → SRAM）、清零 .bss 段
⑤ 调用 SystemInit() → 调用 main()
⑥ main() 中初始化 HAL → 配置外设 → while(1) 主循环
```

### 向量表与 BOOT 配置

| BOOT1 | BOOT0 | 启动区域 |
| --- | --- | --- |
| x | 0 | 主 Flash（正常运行） |
| 0 | 1 | 系统存储器（出厂 Bootloader，可串口/USB 下载） |
| 1 | 1 | 内嵌 SRAM（调试用） |

> 量产常用做法：BOOT0 接地，通过 **IAP（用户 Bootloader）** 实现固件升级。

### 存储规划建议（以 F103C8T6：64 KB Flash / 20 KB RAM 为例）

| 区域 | 大小 | 内容 |
| --- | --- | --- |
| Bootloader | 8~16 KB | 升级逻辑、通信协议 |
| 应用区 | 40~48 KB | 主程序 |
| 参数区 | 1~2 KB | 配置参数（模拟 EEPROM） |
| RAM | 20 KB | 全局变量 + 堆 + 各任务栈（栈用 1~2 KB，中断栈留足） |

## 九、入门实践路线

```
第 1 步  最小系统：供电 + 8 MHz 晶振 + 32.768 kHz + 复位电路 + BOOT0 下拉 + SWD 排针
第 2 步  点灯：GPIO 输出（CubeMX 生成，理解初始化三步：时钟/引脚/模式）
第 3 步  串口：UART 收发 + printf 重定向（调试的核心工具）
第 4 步  中断：EXTI 按键 + NVIC 优先级配置
第 5 步  定时器：TIM 定时中断 + PWM 输出（调 LED 亮度 / 舵机 / 电机）
第 6 步  模拟：ADC 采集（电压、光敏、电位器）+ DMA 搬运
第 7 步  总线：I²C 读传感器（如 MPU6050）+ SPI 驱动屏或 Flash
第 8 步  进阶：RTC + 看门狗 + 低功耗模式 + Flash 参数存取
第 9 步  系统：移植 FreeRTOS，多任务 + 队列 + 信号量
第 10 步 项目：数据采集 → 显示 → 无线上报 → OTA 升级，完整走一遍
```

## 十、常见坑与经验

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 外设完全不工作 | **忘记使能外设/GPIO 时钟** | 检查 `__HAL_RCC_xxx_CLK_ENABLE()` |
| 程序烧一次就再也连不上 | 禁用了 SWD 引脚（PA13/PA14）或进了低功耗 | BOOT0=1 进系统存储器擦除，或连复位瞬间下载 |
| 串口乱码 | 波特率算错、HSE 未起振仍按 72 MHz 计算 | 核对时钟源与分频，测实际波形 |
| 定时器周期不对 | APB 分频后定时器时钟 ×2 被忽略 | 查时钟树，确认 TIMxCLK |
| ADC 值不稳 | 参考电压/地噪声、采样时间太短 | 加去耦、延长采样时间、多次平均 |
| HardFault | 栈溢出、空指针、数组越界 | 查栈帧 PC 值、加大栈、开 `-fstack-usage` |
| I²C 卡死 | 从机未应答、总线被拉低 | 加超时、总线恢复（发 9 个时钟） |
| Flash 写入失败 | 未解锁、未按页擦除、地址越界 | 先 Unlock → Erase → Program → Lock |
| 功耗下不来 | 未关外设时钟、悬空引脚、调试口耗电 | 逐个关时钟、引脚配模拟输入、关闭调试 |
| 移植到国产芯片后异常 | 时序/时钟差异、HAL 版本不同 | 对照数据手册逐项核对，慎用未公开行为 |

### 经验总结

- **先跑通最小系统与串口**，再叠加外设，出问题好定位。
- **CubeMX 只生成框架**，业务代码写在 `USER CODE BEGIN/END` 区域内，重新生成不会丢。
- **版本管理很关键**：固件库版本、CubeMX 版本、工程配置都要记录。
- **量产前必做**：看门狗、掉电保护、参数校验、升级失败回滚、老化测试。
- **不要迷信高配**：够用就好，F103/G0 能解决的不要上 H7。

## 十三、小结

- STM32 是 **ARM Cortex-M 内核 + ST 外设 + 完整生态** 的 MCU 家族，凭借资料丰富、系列齐全、引脚兼容成为事实标准。
- 命名规则 `STM32 [系列] [子系列] [引脚] [Flash] [封装] [温度]`，掌握后可直接从型号读出规格。
- 学习主线：**时钟树 → GPIO → 串口 → 中断 → 定时器 → ADC/DMA → 通信总线 → RTOS**。
- 开发范式：**CubeMX 配 + HAL 编 + ST-Link 调**，新项目首选 G0/G4/L4/U5（老 F1 适合入门与存量）。
- 关键心法：**外设不工作先查时钟，系统跑飞先查栈与指针**。
