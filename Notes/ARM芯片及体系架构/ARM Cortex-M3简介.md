> 记录时间：2026-02-14

## 一、Cortex-M3 是什么

**Cortex-M3** 是 ARM 公司于 2004 年随 ARMv7-M 架构推出的 32 位微控制器内核，是 Cortex-M 家族中承上启下的主力型号：

- 向上：性能高于 Cortex-M0/M0+；
- 向下：不带 FPU 与 DSP 扩展，比 Cortex-M4/M7 更简单、更便宜；
- 定位：**通用控制类 MCU 的性价比之选**。

一句话概括：

> Cortex-M3 = ARMv7-M 架构 + Thumb-2 指令集 + 哈佛总线 + NVIC 中断系统 + 3 级流水线，主打高性能与低成本控制。

### 关键规格

| 项目 | 参数 |
| --- | --- |
| 架构版本 | ARMv7-M（仅支持 Thumb-2，不再支持纯 ARM 指令） |
| 位宽 | 32 位 |
| 流水线 | 3 级（取指 / 译码 / 执行） |
| 中断数 | 最多 240 个外部中断 + 16 个系统异常 |
| 中断优先级 | 最多 8 位（256 级），实际由厂商裁剪 |
| 总线 | 哈佛结构：指令总线（I-Code/D-Code）+ 系统总线 |
| 存储器保护 | 可选 MPU（8 个区域） |
| 调试 | SWD（2 线）/ JTAG（4~5 线），支持 6 个硬件断点 |
| 典型主频 | 24 MHz ~ 200 MHz（芯片实现相关） |
| 性能 | 约 1.25 DMIPS/MHz |
| 功耗 | 典型 μA/MHz 级低功耗设计 |
| 是否带 FPU | **不带**（这是与 M4F 的核心区别） |

### 与相邻内核对比

| 对比项 | Cortex-M0+ | **Cortex-M3** | Cortex-M4 | Cortex-M7 |
| --- | --- | --- | --- | --- |
| 架构 | ARMv6-M | **ARMv7-M** | ARMv7E-M | ARMv7E-M |
| 流水线 | 2 级 | **3 级** | 3 级 | 6 级（双发射） |
| 指令集 | Thumb + 少量 Thumb-2 | **完整 Thumb-2** | Thumb-2 | Thumb-2 |
| 硬件除法 | 无 | **有**（2~12 周期） | 有 | 有 |
| DSP 指令 | 无 | **无** | 有 | 有 |
| FPU | 无 | **无** | 可选单精度 | 可选双精度 |
| MPU | 有（8 区） | 可选（8 区） | 可选 | 有（16 区） |
| Cache | 无 | 无 | 无 | 有（I/D Cache） |
| 性能 | ~0.95 DMIPS/MHz | **~1.25 DMIPS/MHz** | ~1.25 + DSP | ~2.14 DMIPS/MHz |
| 典型型号 | STM32L0、RP2040 | **STM32F103、LPC1768** | STM32F407 | STM32H7 |

> 结论：**需要浮点或 DSP 算法选 M4/M7；只做逻辑控制与通信，M3 更划算。**

## 二、内核内部结构

```

│                                                                    │
│   ┌──────────────┐    ┌──────────────┐    ┌──────────────────┐    │
│   │  I-Code 总线 │    │  D-Code 总线 │    │  系统总线(System) │     │

│          │                   │                     │              │

└────────────────────────────────────────────────────────────────────┘
```

### 三大总线接口

| 总线 | 作用 | 访问对象 |
| --- | --- | --- |
| **I-Code** | 取指令 | Flash / 代码区（0x0000_0000 起） |
| **D-Code** | 取数据 | Flash 中的常量、字面量池 |
| **System** | 数据访问 | SRAM、外设寄存器 |

> **哈佛结构的好处**：取指令与取数据可同时进行，避免冯·诺依曼结构的总线争用，这是 M3 性能优于 8 位机的重要原因。

## 三、寄存器组

Cortex-M3 有 **16 个通用寄存器（R0–R15）+ 若干特殊寄存器**。

### 通用寄存器

| 寄存器 | 别名 | 用途 |
| --- | --- | --- |
| R0–R7 | 低寄存器 | 所有 16 位 Thumb 指令都可访问，最常用 |
| R8–R12 | 高寄存器 | 仅 32 位 Thumb-2 指令可访问 |
| R13 | **SP**（栈指针） | 当前栈顶；MSP/PSP 由 CONTROL 寄存器选择 |
| R14 | **LR**（链接寄存器） | 保存子程序返回地址；异常返回时也用（EXC_RETURN） |
| R15 | **PC**（程序计数器） | 指向当前指令，读出的值 = 当前地址 + 4（流水线效应） |

### 双栈指针机制（M3 特色）

- **MSP（主栈指针）**：复位后默认使用；异常处理**始终**使用 MSP。
- **PSP（进程栈指针）**：由 RTOS 使用，为每个任务分配独立栈。
- 通过 `CONTROL[1]` 位切换；线程模式下可用 PSP，Handler 模式强制用 MSP。

> 意义：**任务栈与中断栈分离**，任务栈溢出不会直接破坏中断处理，提高系统健壮性。

### 特殊寄存器（不可直接用通用指令访问，需 MRS/MSR）

| 寄存器 | 全称 | 关键位与作用 |
| --- | --- | --- |
| **xPSR** | 组合程序状态寄存器 | APSR（N/Z/C/V/Q 标志）+ IPSR（异常号）+ EPSR（T 位等） |
| **PRIMASK** | 中断屏蔽（优先级） | 置 1 屏蔽除 NMI/HardFault 外的所有中断 |
| **FAULTMASK** | 故障屏蔽 | 置 1 屏蔽除 NMI 外全部异常（含 HardFault） |
| **BASEPRI** | 优先级屏蔽 | 屏蔽优先级数值 ≥ 设定值的中断（做临界区最灵活） |
| **CONTROL** | 控制寄存器 | bit0 特权/非特权，bit1 选择 SP（MSP/PSP），bit2 FPCA（M4 才有） |

**xPSR 中的 APSR 标志位**

| 标志 | 名称 | 含义 |
| --- | --- | --- |
| N | Negative | 结果为负 |
| Z | Zero | 结果为零 |
| C | Carry/Borrow | 进位/借位 |
| V | Overflow | 有符号溢出 |
| Q | Saturation | 饱和运算发生（DSP 相关） |

## 四、操作模式与特权级

Cortex-M3 有**两种模式 × 两种特权级**的组合：

| 模式 | 说明 | 使用的栈 |
| --- | --- | --- |
| **线程模式（Thread）** | 执行普通应用程序 | MSP 或 PSP（由 CONTROL 决定） |
| **处理模式（Handler）** | 执行异常/中断服务程序 | 强制 MSP |

| 特权级 | 能力 |
| --- | --- |
| **特权级（Privileged）** | 可访问所有寄存器与资源，可改 CONTROL |
| **非特权级（Unprivileged）** | 受限访问，写某些寄存器会触发故障（用于 MPU 隔离） |

```
复位 → 线程模式 + 特权级 + 使用 MSP
   ├─ 发生中断 → 处理模式 + 特权级（用 MSP），执行 ISR
   │        └─ 异常返回 → 回到线程模式（自动恢复）
   └─ 软件可通过 CONTROL 切到非特权级或改用 PSP
```

> 实际开发中：裸机基本全程特权级 + MSP；RTOS 让任务跑在 PSP 上，以便快速切换上下文。

## 五、存储器映射

Cortex-M3 采用**固定存储器映射**，4 GB 地址空间分成 8 个 512 MB 区域：

| 地址范围                        | 区域             | 用途                        |
| --------------------------- | -------------- | ------------------------- |
| `0x0000_0000 – 0x1FFF_FFFF` | **Code**       | 代码区，通常映射 Flash（可重映射）      |
| `0x2000_0000 – 0x3FFF_FFFF` | **SRAM**       | 片上 SRAM（位带区在首 1 MB）       |
| `0x4000_0000 – 0x5FFF_FFFF` | **Peripheral** | 外设寄存器（位带区在首 1 MB）         |
| `0x6000_0000 – 0x9FFF_FFFF` | **外部 RAM**     | 外扩 SDRAM / NOR 等          |
| `0xA000_0000 – 0xDFFF_FFFF` | **外部设备**       | 外扩外设                      |
| `0xE000_0000 – 0xE00F_FFFF` | **私有外设总线 PPB** | NVIC、SysTick、SCB、MPU、调试组件 |
| `0xE010_0000 – 0xFFFF_FFFF` | 厂商自定义          | 内部 ROM、特殊功能               |

### 关键地址速记

| 地址 | 内容 |
| --- | --- |
| `0x0000_0000` | 初始 MSP 值（向量表第 0 项） |
| `0x0000_0004` | 复位向量（Reset_Handler 地址） |
| `0x0800_0000` | STM32 上 Flash 的实际映射起始地址 |
| `0x2000_0000` | SRAM 起始 |
| `0xE000_E100` | NVIC 中断使能寄存器组 |
| `0xE000_E000` | SysTick 控制寄存器 |

### 位带（Bit-Banding）——M3 的实用特性

- 把 SRAM/外设的**每个位**映射到别名区的一个 32 位字，实现**原子级位操作**。
- 别名地址公式：`别名地址 = 别名基址 + (字节偏移 × 32) + (位号 × 4)`
- SRAM 别名区：`0x2200_0000`；外设别名区：`0x4200_0000`。
- 好处：一条 `STR` 指令即可置位/清零，天然原子，无需读-改-写，适合操作共享标志。

> 注：ARMv8-M 已取消位带特性，M3/M4 才有。

## 六、Thumb-2 指令集

Cortex-M3 **只支持 Thumb-2**，不再支持传统 32 位 ARM 指令集。

### 特点

- **混合位宽**：16 位指令（代码密度高）+ 32 位指令（功能强），自动组合。
- **性能与密度兼顾**：比纯 Thumb 性能高，比纯 ARM 代码小约 30%。
- **对齐**：指令按半字（2 字节）对齐；跳转地址最低位恒为 1（表示 Thumb 状态）。

### 常用指令分类

| 类别   | 指令举例                                                      | 说明                          |
| ---- | --------------------------------------------------------- | --------------------------- |
| 数据传送 | `MOV` `MOVW` `MOVT` `LDR` `STR` `LDM` `STM` `PUSH` `POP`  | `MOVW/MOVT` 组合可加载任意 32 位立即数 |
| 算术运算 | `ADD` `SUB` `ADC` `SBC` `RSB` `MUL` `MLA` `UDIV` `SDIV`   | 硬件除法是 M3 相对 M0 的重要优势        |
| 逻辑运算 | `AND` `ORR` `EOR` `BIC` `MVN`                             | 位操作常用 `BIC`（清位）与 `ORR`（置位）  |
| 移位   | `LSL` `LSR` `ASR` `ROR` `RRX`                             | 可与其他指令组合成桶形移位               |
| 比较   | `CMP` `CMN` `TST` `TEQ`                                   | 只更新标志位                      |
| 跳转   | `B` `BL` `BX` `BLX` `CBZ` `CBNZ`                          | `BL` 自动保存返回地址到 LR           |
| 条件执行 | `IT`（If-Then）块                                            | 最多 4 条指令条件执行，减少跳转开销         |
| 系统   | `MRS` `MSR` `CPSIE` `CPSID` `DSB` `DMB` `ISB` `WFI` `WFE` | 访问特殊寄存器、屏障、低功耗              |
| 饱和运算 | `SSAT` `USAT`                                             | 防溢出，信号处理相关（M4 更强）           |

### 三段经典汇编示例

```asm
; 1) 关中断 / 开中断（临界区）
    CPSID   I           ; PRIMASK = 1，关中断
    ; ... 临界区代码 ...
    CPSIE   I           ; PRIMASK = 0，开中断

; 2) 用位带或位操作点亮 LED（PA5）
    LDR     R0, =0x40020014   ; GPIOA->ODR
    LDR     R1, [R0]
    ORR     R1, R1, #(1 << 5) ; 置位 PA5
    STR     R1, [R0]

; 3) 调用子程序
    BL      delay_ms          ; 返回地址存入 LR
```

### 内联汇编（C 语言中访问特殊寄存器）

```c
/* 读取 PRIMASK 并关中断，返回原状态 */
static inline uint32_t enter_critical(void)
{
    uint32_t pm;
    __asm volatile ("MRS %0, PRIMASK" : "=r"(pm));
    __asm volatile ("CPSID I" ::: "memory");
    return pm;
}

static inline void exit_critical(uint32_t pm)
{
    __asm volatile ("MSR PRIMASK, %0" :: "r"(pm) : "memory");
}
```

> CMSIS 已提供 `__disable_irq()` / `__enable_irq()` / `__get_PRIMASK()` 等内建函数，一般无需手写汇编。

## 七、异常与中断模型

### 异常编号表

| 编号 | 类型 | 名称 | 优先级 | 说明 |
| --- | --- | --- | --- | --- |
| 1 | 系统 | **Reset** | −3（最高） | 上电/复位 |
| 2 | 系统 | **NMI** | −2 | 不可屏蔽中断 |
| 3 | 系统 | **HardFault** | −1 | 所有故障的兜底处理 |
| 4 | 系统 | MemManage | 可编程 | MPU 违规访问 |
| 5 | 系统 | BusFault | 可编程 | 总线错误 |
| 6 | 系统 | UsageFault | 可编程 | 非法指令/除零等 |
| 7–10 | — | 保留 | — | — |
| 11 | 系统 | **SVCall** | 可编程 | 系统服务调用（RTOS 用） |
| 12 | 系统 | Debug Monitor | 可编程 | 调试监控 |
| 13 | — | 保留 | — | — |
| 14 | 系统 | **PendSV** | 可编程 | 可挂起系统调用，RTOS 上下文切换专用 |
| 15 | 系统 | **SysTick** | 可编程 | 系统滴答定时器 |
| 16 起 | 外部 | IRQ0…IRQ239 | 可编程 | 厂商外设中断（如 EXTI0、USART1） |

### 优先级机制

- 优先级数值**越小优先级越高**；分为**抢占优先级**与**子优先级**（由 PRIGROUP 划分位数）。
- 高抢占优先级可打断低抢占优先级的 ISR（**嵌套中断**）。
- 相同抢占优先级时，子优先级高者先执行，但不能互相抢占。
- **尾链（Tail-chaining）**：上一个 ISR 结束后立即进入下一个挂起中断，省去出栈入栈，仅需 6 个周期。
- **晚到（Late-arriving）**：更高优先级中断在入栈期间到达，直接改取该中断向量，无需重复入栈。

### 异常处理流程（硬件自动完成）

```
中断发生
   ↓
① 入栈（Stacking）：自动把 xPSR、PC、LR、R12、R3-R0 压栈（8 个字）
   ↓
② 取向量：从向量表读出 ISR 地址，更新 PC
   ↓
③ 更新 LR = EXC_RETURN（特殊的返回标记）
   ↓
④ 切换到处理模式，使用 MSP，执行 ISR
   ↓
⑤ 出栈（Unstacking）：异常返回时自动恢复寄存器
```

**EXC_RETURN 的常见值**

| 值 | 含义 |
| --- | --- |
| `0xFFFF_FFF1` | 返回处理模式（Handler），用 MSP |
| `0xFFFF_FFF9` | 返回线程模式，用 MSP |
| `0xFFFF_FFFD` | 返回线程模式，用 PSP（RTOS 任务） |

### 三个必备的故障处理函数

```c
void HardFault_Handler(void)  { while (1) { /* 记录 LR/PC/PSR 便于定位 */ } }
void MemManage_Handler(void)  { while (1); }
void BusFault_Handler(void)   { while (1); }
```

> 调试技巧：HardFault 时查看**栈帧**中的 PC 值，即可定位出错的指令地址。

## 八、SysTick 与 NVIC 编程要点

### SysTick（24 位递减计数器）

```
CTRL  : 使能、时钟源（内核/8 分频）、中断使能
LOAD  : 重装载值（决定中断周期）
VAL   : 当前计数值（写任意值可清零）
CALIB : 校准值（可判断是否精确 10 ms）
```

常用于：
- 裸机的毫秒延时基准；
- RTOS 的系统节拍（1 ms 或 10 ms tick）。

### NVIC 核心寄存器

| 寄存器 | 作用 |
| --- | --- |
| `ISER` | 中断使能（写 1 使能） |
| `ICER` | 中断禁用 |
| `ISPR` / `ICPR` | 挂起 / 解挂中断 |
| `IABR` | 当前活动的中断 |
| `IPR` | 每个中断的优先级（8 位，实际可用位数由厂商决定） |

### CMSIS 常用 API（免记寄存器）

```c
NVIC_EnableIRQ(USART1_IRQn);
NVIC_DisableIRQ(USART1_IRQn);
NVIC_SetPriority(USART1_IRQn, 1);
NVIC_SetPriorityGrouping(NVIC_PRIORITYGROUP_4);   // 4 位全为抢占优先级
__disable_irq();  __enable_irq();                  // 全局开关中断
__WFI();                                           // 等待中断（低功耗）
```

## 九、低功耗与调试

### 低功耗指令与模式

| 指令 | 作用 |
| --- | --- |
| `WFI` | Wait For Interrupt：进入睡眠，任意中断唤醒 |
| `WFE` | Wait For Event：等待事件，配合 `SEV` 使用 |
| `SEV` | 发送事件，唤醒其他核/自身 |

配合芯片的 Sleep / Deep-Sleep / Standby 模式与 WIC，可实现 μA 级待机。

### 调试特性

| 特性 | 说明 |
| --- | --- |
| SWD / SW-JTAG | 2 线（SWCLK + SWDIO）即可下载与调试 |
| 硬件断点 | 6 个指令断点 + 2 个数据观察点 |
| 跟踪 | ITM（printf 调试）、ETM（指令跟踪，部分型号需要引脚） |
| 内核调试寄存器 | DHCSR、DCRSR、DCRDR 等，可查看/修改寄存器 |
| 常见坑 | 复用 SWD 引脚（PA13/PA14）后需要特殊方式才能再次下载 |

## 十一、学习与开发建议

### 上手顺序

```
最小系统（供电+晶振+复位+Boot）→ 点灯（GPIO）→ 串口打印（UART）
→ 定时器/中断 → 按键与外部中断 → ADC/PWM → I²C/SPI 外设
→ DMA → 看门狗/RTC/低功耗 → 移植 FreeRTOS
```

### 必读三份资料

| 资料 | 内容 |
| --- | --- |
| 《Cortex-M3 权威指南》（Joseph Yiu） | 内核原理最权威，寄存器与异常模型讲得最透 |
| 芯片的 **Reference Manual** | 外设寄存器定义与时钟树 |
| 芯片的 **Datasheet** | 引脚、电气参数、封装 |
| **CMSIS** 规范文档 | 内核访问接口标准，跨厂商通用 |

### 常见坑

- **忘记使能外设时钟**（RCC），外设"完全没反应"的第一嫌疑。
- **栈大小不够**：局部大数组放栈上导致 HardFault，改静态分配或加大栈。
- **中断中做耗时操作**：ISR 应尽量短，只置标志/发信号量。
- **共享变量未加 `volatile`**：编译器优化导致读到旧值。
- **优先级配置错误**：抢占位与子优先级分组不符预期，嵌套行为异常。
- **滥用全局关中断**：用 `BASEPRI` 只屏蔽必要优先级，减少实时性损失。
- **PC 读值误解**：读 PC 得到的是"当前地址 + 4"，写 PC 会引发跳转。

## 十三、小结

- **Cortex-M3 = ARMv7-M + Thumb-2 + 哈佛三总线 + NVIC + 3 级流水线**，约 1.25 DMIPS/MHz，不带 FPU 与 DSP 扩展。
- 核心特色四件套：**双栈指针（MSP/PSP）、NVIC 嵌套中断、位带原子操作、硬件除法**。
- 编程模型记住：**16 个通用寄存器 + xPSR/PRIMASK/BASEPRI/FAULTMASK/CONTROL 五个特殊寄存器**，两种模式两种特权级。
- 异常处理是硬件自动入栈出栈，理解 **EXC_RETURN** 与 **PendSV** 是读懂 RTOS 移植代码的关键。
- 学习路径：先用 STM32F103 把 GPIO/串口/定时器/中断跑通，再深入 NVIC 优先级与 RTOS 移植。
