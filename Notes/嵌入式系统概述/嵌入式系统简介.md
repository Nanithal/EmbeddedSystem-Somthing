## 一、什么是嵌入式系统

**嵌入式系统（Embedded System）** 是指嵌入到宿主设备（对象体系）中、为特定应用而设计的专用计算机系统。它以应用为中心，以计算机技术为基础，软硬件可裁剪，对功能、可靠性、成本、体积、功耗有严格要求。

一句话概括：

> 嵌入式系统 = 硬件（微处理器为核心）+ 软件（固化在存储器中）+ 特定功能 + 嵌入到宿主设备中

### 核心特征

| 特征 | 含义 |
| --- | --- |
| 专用性 | 面向特定任务，不是通用计算机 |
| 嵌入性 | 作为宿主设备的一部分，通常用户"看不见"它 |
| 软硬件可裁剪 | 按需增删功能，最低成本满足需求 |
| 资源受限 | CPU 主频、内存、存储、功耗都很有限 |
| 实时性 | 很多场景要求在规定时间内完成响应 |
| 高可靠性 | 长期无人值守运行，允许的失效概率极低 |
| 生命周期长 | 产品寿命常达 5～15 年 |

### 与通用计算机的区别

| 对比项 | 通用计算机（PC） | 嵌入式系统 |
| --- | --- | --- |
| 目的 | 通用计算、多任务办公娱乐 | 完成特定功能 |
| 软件 | 可自由安装卸载 | 固化（烧写在 ROM/Flash 中） |
| 人机界面 | 键盘、鼠标、显示器为主 | 可能只有按键、指示灯，甚至无界面 |
| 资源 | 充裕（GB 级内存、多核高频） | 紧张（KB～MB 级内存、低主频） |
| 实时性 | 一般不作要求 | 常为硬性指标 |
| 升级维护 | 用户自行升级 | 由厂商通过固件/OTA 更新 |

## 二、嵌入式系统的组成

```
                    ┌──────────────────────────────┐
                    │        嵌入式系统             │
      ┌─────────────┴─────────────┐  ┌─────────────┴─────────────┐
      │          硬件层            │  │          软件层            │
      │  ┌──────────────────────┐ │  │  ┌──────────────────────┐ │
      │  │ 嵌入式处理器(MCU/MPU) │ │  │  │   应用软件            │ │
      │  ├──────────────────────┤ │  │  ├──────────────────────┤ │
      │  │ 存储器 RAM/ROM/Flash  │ │  │  │   中间件/协议栈       │ │
      │  ├──────────────────────┤ │  │  ├──────────────────────┤ │
      │  │ 外设与接口            │ │  │  │   操作系统(可选/RTOS) │ │
      │  │ GPIO/UART/SPI/I2C/   │ │  │  ├──────────────────────┤ │
      │  │ ADC/PWM/USB/以太网    │ │  │  │   板级支持包 BSP      │ │
      │  ├──────────────────────┤ │  │  ├──────────────────────┤ │
      │  │ 电源/时钟/复位/看门狗 │ │  │  │   设备驱动            │ │
      │  └──────────────────────┘ │  │  └──────────────────────┘ │
      └───────────────────────────┘  └───────────────────────────┘
```

### 1. 硬件层

- **嵌入式处理器**：整个系统的核心，负责运算与控制。
- **存储器**：
  - RAM：运行时数据、堆栈；
  - ROM/Flash：存放固件和常量数据；
  - EEPROM：保存需掉电不丢失的配置参数。
- **外设与接口**：GPIO、UART、SPI、I²C、CAN、ADC/DAC、PWM、定时器、USB、以太网、无线模块等。
- **辅助电路**：电源管理、时钟晶振、复位电路、看门狗（Watchdog）。

### 2. 软件层（自底向上）

1. **设备驱动 / BSP**：直接操作寄存器，屏蔽硬件差异。
2. **操作系统（可选）**：裸机（前后台程序）或 RTOS（FreeRTOS、RT-Thread、μC/OS）或嵌入式 Linux。
3. **中间件**：文件系统、TCP/IP 协议栈、GUI、数据库、通信协议栈。
4. **应用软件**：实现产品最终业务逻辑。

> 简单产品可只用**裸机 + 主循环（前后台系统）**；复杂或强实时产品才需要 RTOS。

## 三、嵌入式处理器的分类

| 类型         | 特点                    | 典型代表                      | 应用举例           |
| ---------- | --------------------- | ------------------------- | -------------- |
| MCU（微控制器）  | 芯片内集成 CPU+存储+外设，单芯片方案 | STM32、ESP32、AVR、8051、GD32 | 家电、传感器节点、电机控制  |
| MPU（微处理器）  | 需外接内存，性能强，常跑 Linux    | ARM Cortex-A 系列、i.MX、全志   | 手机、路由器、工业 HMI  |
| DSP        | 擅长数字信号运算（乘加、流水）       | TI C2000/C5000、ADI SHARC  | 音频处理、电机矢量控制、通信 |
| FPGA / SoC | 硬件可编程、并行度高            | Xilinx Zynq、Altera SoC    | 高速采集、图像处理、协议加速 |
| ASIC / SoC | 专用定制芯片，量产成本低          | 各类定制芯片                    | 消费电子大批量产品      |

### 常见内核架构

- **ARM**：Cortex-M（微控制器）、Cortex-R（实时）、Cortex-A（应用处理器）——目前市场主流。
- **RISC-V**：开源指令集，近年发展迅速。
- **x86 / MIPS / PowerPC**：特定领域仍有使用。
- **8051 / AVR / PIC**：经典 8 位机，教学与低成本场景。

## 四、嵌入式操作系统

| 系统            | 类型       | 特点                    |
| ------------- | -------- | --------------------- |
| 裸机（前后台）       | 无 OS     | 结构简单、开销最小，适合单一任务      |
| FreeRTOS      | 硬实时 RTOS | 免费开源、代码小、移植方便、生态好     |
| RT-Thread     | 实时 OS    | 国产、组件丰富、中文资料多         |
| μC/OS-II/III  | 硬实时 RTOS | 经典教学与工业用，源码规范、可认证     |
| Zephyr        | 实时 OS    | Linux 基金会维护，支持多架构、模块化 |
| 嵌入式 Linux     | 分时 OS    | 功能强大、驱动生态全，但实时性与资源要求高 |
| VxWorks / QNX | 商业硬实时    | 航空航天、医疗等高可靠领域         |

### 实时性概念

- **硬实时**：超时即失败（如安全气囊、电机换相）。
- **软实时**：偶尔超时可接受（如视频播放、界面刷新）。
- **衡量指标**：中断延迟、任务切换时间、最坏执行时间（WCET）。

## 五、嵌入式系统开发流程

```
需求分析 → 硬件选型与设计 → 软件开发 → 联调测试 → 量产与维护
   ↑                                                │
   └────────────── 迭代 / OTA 升级 ─────────────────┘
```

1. **需求分析**：功能、性能、功耗、成本、环境（温度/振动/电磁）。
2. **硬件设计**：选芯片 → 原理图 → PCB → 打样焊接与上电测试。
3. **软件开发**：
   - 搭建交叉编译工具链；
   - 移植/配置 Bootloader、OS、驱动；
   - 编写应用逻辑；
   - 通过仿真器（JTAG/SWD）下载与调试。
4. **测试验证**：功能测试、边界测试、EMC、高低温、老化、功耗测试。
5. **量产与维护**：烧录工装、产测程序、版本管理与固件升级（OTA）。

### 开发中常用的"交叉"概念

- **交叉编译**：在 PC（宿主机）上编译出目标板可执行代码。
- **交叉调试**：JTAG/SWD + GDB/IDE，单步、断点、查看寄存器与内存。
- **烧写**：ISP（串口）、SWD、USB DFU、SD 卡等。

## 七、发展趋势

- **AI 边缘化（Edge AI / TinyML）**：把推理放到终端，降低时延与隐私风险。
- **RISC-V 生态崛起**：开源指令集带来芯片设计门槛下降。
- **异构多核 SoC**：Cortex-A + Cortex-M + NPU/DSP 协同。
- **功能安全与信息安全**：ISO 26262、IEC 61508、安全启动与可信执行环境。
- **低功耗与能量采集**：面向电池供电与无源传感节点。
- **端云协同与 OTA**：设备可远程升级、诊断与运维。
- **开发方式变化**：模型驱动开发、自动化测试、CI/CD 进入嵌入式。

## 八、学习路线建议（个人笔记）

1. **基础**：C 语言（指针、结构体、位运算）、数字电路基础、计算机组成原理。
2. **入门**：51 或 STM32 → 点亮 LED → 按键/串口 → 定时器/中断 → ADC/PWM。
3. **进阶**：外设协议（SPI/I²C/CAN）、RTOS（任务、信号量、队列、优先级反转）。
4. **上层**：嵌入式 Linux（U-Boot、内核裁剪、设备树、驱动模型）。
5. **实践**：做一个小项目（如温湿度采集 + 屏幕显示 + 无线上报），完整走一遍需求→设计→编码→调试→优化。

### 常见调试思路

- 先确认**电源与时钟**是否正常，再看复位与启动。
- 从最小系统出发：能下载 → 能跑通串口打印 → 再逐个加外设。
- 问题分层定位：硬件（示波器/万用表）→ 驱动寄存器 → 应用逻辑。
- 保留日志与版本记录，方便回溯。

## 十、小结

- 嵌入式系统的本质是**面向特定应用的专用计算机系统**，强调专用、嵌入、可裁剪、资源受限与高可靠。
- 结构上分为**硬件层**与**软件层**，软件层可简可繁：裸机能做的，不必上 OS；需要实时与多任务时，选合适的 RTOS。
- 开发的核心能力是：**看懂硬件手册、写对寄存器操作、用工具把问题定位到具体一层**。
- 选择方案时始终权衡五件事：**功能、性能（含实时性）、功耗、成本、可靠性**。
